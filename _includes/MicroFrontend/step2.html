Child2 vite config and app.tsx:
    
        import { defineConfig } from "vite";
        import react from "@vitejs/plugin-react";
        import federation from "@originjs/vite-plugin-federation";

        export default defineConfig({
        plugins: [
            react(),
            federation({
            name: "remoteApp2",
            filename: "remoteEntry.js", 
            exposes: {
                "./App": "./src/App.tsx", 
            },
            shared: ['react', "react-dom"]
            }),
        ],
        build: {
            modulePreload: false,
            target: 'esnext',
            minify: false,
            cssCodeSplit: false
        },
        server: {
            cors: true,
            headers: {
            "Access-Control-Allow-Origin": "*", 
            },
        },
        preview: {
            headers: {
            "Access-Control-Allow-Origin": "*", 
            },
        },
        });

    

    
        import { useState } from 'react'
        import viteLogo from '/vite.svg'
        import './App.css'

        function App() {
        const [count, setCount] = useState(0)

        return (
            <>
            <div>
            <a href="https://vite.dev" target="_blank">
            <img src={viteLogo} className="logo" alt="Vite logo" />
            </a>
            </div>
            <h1>Vite + React Page2</h1>
            <div className="card">
            <button onClick={() => setCount((count) => count + 1)}>
                count is {count}
                </button>
                <p>
                Edit <code>src/App.tsx</code> and save to test HMR
                </p>
                </div>
                <p className="read-the-docs">
                Click on the Vite and React logos to learn more
                </p>
                </>
        )
        }

        export default App

Install & Build & Run:

Let's run 3 commands respectively in 3 repos. 

        
            npm install
            npm run build
            npm run serve

localhost 5000 & 5001 & 5002 will open in your browser. We can see the flow in network tab.

Blocker problems of other applications do not stop the development or deployment of other teams.

Shared package downloaded 1 time. The biggest impact on performance is that repetitive packages are not downloaded again.

Any structure on dom can be used as communication. redux can be exported with expose method. event based structure can be established.

But there is a problem in the application css. when I return to the home page, the background of the page looks different. whereas when I first started the application, the home page had a white background. What can we do here?

There is some problem when you try to find plugins. Module federation has a soluttion and they support lots of tools. and you can find the their works in github module federation page. Also other tools support the module federation rules. for examle about vite & module federation; you can find 2 different plugin. one of them created from vite team other one developed from module federation team. Orijinjs and moduleFederation are try to solve same problems.

Expose and remote showing same point to developer. Configuration is not more complex as you can see. And that way is solved more issue than we talked.

Other Usages:

We can create component repo and expose via module federation. We dont need to use component repo structure or architecture.

We can support all framework or applications functions in one place without big structures. About Utils repo; every team or frameworks can use same functions or feature. As we talked before we can create a repo to storing all utils fuctions in one place it will affect to finding functions or helpers.

Enviroment base configuration can be used. We can use different configuration for different enviroments. and we can store the our configuration with this solution. We dont need to create configuration repo.

Final:

Module federation is an approach and an architecture. We should choose the best solution for our project. We can use the module federation with different frameworks, teams, repos, configurations.

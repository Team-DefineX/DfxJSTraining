Why are Prototypes required?

Let's imagine that we need a car object in our Javascript program: 
    
    let car = {}
    car.brand = 'Volkswagen'
    car.hasElectricModels = true
    car.headquartered = 'Wolfsburg'
    car.numberOfEmployee = 5400

    car.getheadquarteredInfo = function() {
        console.log(`${this.brand} headquartered is ${this.headquartered}`)
    }

    car.getNumberOfEmployeeInfo = function() {
        console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
    }

This code can meet the requirements, but let's consider the scenario where we need multiple car objects. We would probably write a function to perform this task. 

    
    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
        let car = {}
        car.brand = brand
        car.hasElectricModels = hasElectricModels
        car.headquartered = headquartered
        car.numberOfEmployee = numberOfEmployee

        car.getheadquarteredInfo = function() {
            console.log(`${this.brand} headquartered is ${this.headquartered}`)
        }

        car.getNumberOfEmployeeInfo = function() {
            console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
        }

        return car
    }

    var car = Car('Volkswagen', true, 'Wolfsburg', 5400)

    console.log(car)

Output 

    
    {
        brand: "Volkswagen",
        getheadquarteredInfo: function() {
                  console.log(`${this.brand} headquartered is ${this.headquartered}`)
              },
        getNumberOfEmployeeInfo: function() {
                  console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
              },
        hasElectricModels: true,
        headquartered: "Wolfsburg",
        numberOfEmployee: 5400
    }

That works, but is this really the best way to do it?


If you need a million car objects, it's not a good idea to use this method because the getheadquarteredInfo and getNumberOfEmployeeInfo functions will be stored in memory for each object, which is not a good idea.


Instead, if we only create the functions once in the car function and then refer to them inside the function, the getheadquarteredInfo and getNumberOfEmployeeInfo functions will only be created once in memory and won't need to be made again. 

    
    const CarMethods = {
        getheadquarteredInfo : function() {
            console.log(`${this.brand} headquartered is ${this.headquartered}`)
        },
        getNumberOfEmployeeInfo : function() {
            console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
        }
    }

    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
        let car = {}
        car.brand = brand
        car.hasElectricModels = hasElectricModels
        car.headquartered = headquartered
        car.numberOfEmployee = numberOfEmployee

        car.getheadquarteredInfo = CarMethods.getheadquarteredInfo
        car.getNumberOfEmployeeInfo = CarMethods.getNumberOfEmployeeInfo

        return car
    }

    var car = Car('Volkswagen', true, 'Wolfsburg', 5400)

    console.log(car)

Output 

    
    {
        brand: "Volkswagen",
        getheadquarteredInfo: function() {
                  console.log(`${this.brand} headquartered is ${this.headquartered}`)
              },
        getNumberOfEmployeeInfo: function() {
                  console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
              },
        hasElectricModels: true,
        headquartered: "Wolfsburg",
        numberOfEmployee: 5400
    }

However, there are several drawbacks to this strategy. Can you figure it out?


Assume that you need to add a function to the Car object later on. In this situation, we would add our method to CarMethods first, then retrieve the reference from the Car function again. 


    
    const CarMethods = {
        getheadquarteredInfo : function() {
            console.log(`${this.brand} headquartered is ${this.headquartered}`)
        },
        getNumberOfEmployeeInfo : function() {
            console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
        },
        getCompanyInfo : function() {
            console.log(`${this.brand} headquartered is ${this.headquartered} and has ${this.numberOfEmployee} employee`)
        }
    }

    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
        let car = {}
        car.brand = brand
        car.hasElectricModels = hasElectricModels
        car.headquartered = headquartered
        car.numberOfEmployee = numberOfEmployee

        car.getheadquarteredInfo = CarMethods.getheadquarteredInfo
        car.getNumberOfEmployeeInfo = CarMethods.getNumberOfEmployeeInfo
        car.getCompanyInfo = CarMethods.getCompanyInfo

        return car

Even if it's not a major concern, it would be useful to have a single place where we could create these instances and have them reflected in all instances. Javascript prototypes are useful in situations like these.


Prototype

In Javascript, a prototype is basically a property of a function. When a function is created, the Javascript engine automatically assigns a Prototype property to the function. This prototype property is an object, and this object has a property called constructor. As shown in the image below, this constructor property refers to the function that was created.

The prototype property identifies the prototype object being discussed.


We can access the function's prototype property with the syntax functionName.prototype. And using functionName.prototype.constructor, we can access the function object from the Prototype object of a function. If you are confused, let's write some code to clarify the situation.


Creating Objects Using Constructor Functions

Now, let's print our constructor function that takes four parameters, brand, hasElectricModels, headquartered and numberOfEmployee, and the prototype object of this function to the console. 

    
    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
        this.brand = brand
        this.hasElectricModels = brand
        this.headquartered = headquartered
        this.numberOfEmployee = numberOfEmployee
    }

    console.log(Car.prototype)

You will see an output like the one below:


You can see that console.log(Car.prototype) takes us to the prototype object of our function, and as we said, this object has a constructor property. For now, you don't need to worry about the __proto__ property. Now let's print console.log(Car.prototype.constructor) to our console.



When we create a function, the JavaScript engine gives the function a value called prototype. With this property, we can get to the function's prototype object, which has another property called constructor in it. This feature points at a function. Let's prove this now. 

    
    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
        this.brand = brand
        this.hasElectricModels = brand
        this.headquartered = headquartered
        this.numberOfEmployee = numberOfEmployee
    }

    console.log(Car.prototype.constructor === Car)
    console.log(Car.prototype === Car.prototype.constructor.prototype)

The result we should expect in our first log is that the constructor property in the prototype object of our Car function brings us back to the Car function. In the second log, the constructor property on the prototype object of the Car function points back to our function. Then, the prototype of the constructor is equal to Car.prototype.


Output 

    
    true
    true

Let's create a new Car object and print it to the console.



Where are our methods? They were added to the prototype object. However, it does not appear in our car object. There is something else in there. Let's find out what it is.


Our methods are here. It seems that the __proto__ property points to the prototype object. When we create an instance, JavaScript adds a property named __proto__ that points to the prototype object.



If what we have been explaining from the beginning is true, that is, if the __proto__ property points to the prototype object, we should be seeing the methods when we extend it. 

    
    function Car(brand, hasElectricModels, headquartered, numberOfEmployee) {
         this.brand = brand
         this.hasElectricModels = brand
         this.headquartered = headquartered
         this.numberOfEmployee = numberOfEmployee
     }
 
     Car.prototype.getCompanyInfo = function() {
         console.log(`${this.brand} headquartered is ${this.headquartered} and has ${this.numberOfEmployee} employee`)
     }
 
     Car.prototype.getheadquarteredInfo = function() {
         console.log(`${this.brand} headquartered is ${this.headquartered}`)
     }
 
     Car.prototype.getNumberOfEmployeeInfo = function() {
         console.log(`${this.brand} has ${this.numberOfEmployee} employee`)
     }
 
     const car = new Car('Volkswagen', true, 'Wolfsburg', 5400)
 
     console.log(Car.prototype === car.__proto__)

Output 

    
    true

When we create a function, the JavaScript engine automatically creates a Prototype object for that function and adds a prototype property to the function that can be used to access that object. It also adds a property called constructor inside the prototype object, which points to the function.


When we create an instance from the constructor function, a property named __proto__ is added to this instance, and this property points to the prototype object of the function.

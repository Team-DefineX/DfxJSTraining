Node.js Event Loop Mechanism

    The event loop in Node.js is a mechanism that allows Node.js to perform non-blocking I/O operations despite JavaScript being single-threaded. It achieves this by delegating operations to the operating system whenever possible.


Purpose of the Event Loop

  • Handle multiple concurrent operations efficiently without creating multiple threads.
  • Process asynchronous I/O operations such as file system access, network requests, and timers.
  • Enable non-blocking behavior, making it ideal for I/O-intensive applications.


Why Was the Event Loop Needed?

    JavaScript was originally designed to run in browsers with a single-threaded execution model. However, in server-side environments like Node.js, dealing with I/O-heavy operations using a synchronous model would block execution, making it inefficient. To solve this, Node.js implemented asynchronous, non-blocking I/O using an event-driven architecture powered by libuv.


How the Event Loop Works

    Node.js uses libuv, a C++ library that provides an event-driven, non-blocking I/O model with an event loop. The event loop consists of six phases, executed in the following order:

  1. Timers Phase: Executes setTimeout and setInterval callbacks.
  2. Pending Callbacks Phase: Executes I/O callbacks deferred from previous operations.
  3. Idle/Prepare Phase: Internal use only.
  4. Poll Phase: Retrieves new I/O events and executes I/O-related callbacks.
  5. Check Phase: Executes setImmediate callbacks.
  6. Close Callbacks Phase: Executes close event callbacks (e.g., socket closures).

Synchronous Code

Synchronous operations execute in sequence, blocking further execution until completion. 

  
    console.log("Start");

    // Blocking operation
    const result = someSyncFunction();
    console.log(result);

    console.log("End");
  

  
    Start
    Result
    End

Here, someSyncFunction must complete before console.log("End") executes.


Asynchronous Code

Asynchronous operations allow execution to continue without waiting for the operation to complete. 

  
    console.log("Start");

    setTimeout(() => {
        console.log("Timeout Callback Executed");
    }, 2000);

    console.log("End");

Output: 

  
    Start
    End
    Timeout Callback Executed  (After 2 seconds)

The setTimeout callback is executed in the Timers phase of the event loop.


Code Execution in Different Layers
  1. JavaScript Engine (V8) - Executes synchronous JavaScript code.
  2. Libuv (C++ library) - Handles I/O operations asynchronously.
  3. Node.js API - Bridges JavaScript and the system (libuv, OS).
Code Type Execution Layer
Normal JavaScript code V8 Engine
setTimeout, setImmediate Event Loop (Timers, Check Phases)
File System (fs.readFile) Libuv Thread Pool
Network Requests (http.request) Libuv & OS (Non-blocking I/O)
process.nextTick, Promises Microtask Queue (Executes Before Next Event Loop Phase)

Async/Await, Promises, and Task Queues in Node.js

    In modern JavaScript and Node.js, asynchronous programming is heavily reliant on Promises and async/await. These features help in managing non-blocking operations efficiently while keeping the code readable.


1. Promises

A Promise represents a value that may be available now, or in the future, or never. It has three states:

  • Pending: Initial state, neither fulfilled nor rejected.
  • Fulfilled: The operation was successful.
  • Rejected: The operation failed.

Example: Basic Promise 

  
    const myPromise = new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve("Data received!"); // Fulfilled after 2 seconds
        }, 2000);
    });

    myPromise.then((data) => {
        console.log(data); // Output after 2 seconds: "Data received!"
    });
  1. The setTimeout inside the promise executes asynchronously.
  2. When it resolves, the .then() callback is added to the Microtask Queue and executed in the next event loop cycle.

2. Async/Await

async/await is syntactic sugar over Promises that allows writing asynchronous code in a synchronous-like manner.

Example: Using Async/Await 

  
    function fetchData() {
        return new Promise((resolve) => {
            setTimeout(() => {
                resolve("Fetched Data");
            }, 2000);
        });
    }

    async function getData() {
        console.log("Fetching...");
        const data = await fetchData();  // Pauses here until Promise resolves
        console.log(data);
    }

    getData();
    console.log("Execution continues...");
  

  
    Fetching...
    Execution continues...
    Fetched Data
Explanation
  1. The function fetchData returns a Promise.
  2. Inside getData(), await fetchData(); pauses execution until fetchData() resolves.
  3. Meanwhile, "Execution continues..." gets logged.
  4. After 2 seconds, "Fetched Data" is logged.
How Async/Await Works with the Event Loop
  • await does NOT block the entire thread; it only pauses the function execution until the promise resolves.
  • The remaining code continues to execute.
  • The awaited operation's result is processed in the Microtask Queue.

3. Microtask Queue vs. Macrotask Queue

Node.js has two types of task queues:

  1. Microtask Queue (Higher Priority)
    • Includes Promises, process.nextTick()
    • Runs immediately after the current synchronous code before the next event loop phase.
  2. Macrotask Queue (Lower Priority)
    • Includes setTimeout, setImmediate, I/O callbacks
    • Runs in their respective phases in the event loop.

Microtask Example (process.nextTick and Promises) 
  
    console.log("Start");

    process.nextTick(() => console.log("process.nextTick"));
    Promise.resolve().then(() => console.log("Promise resolved"));

    console.log("End");

Output: 

  
    Start
    End
    process.nextTick
    Promise resolved


Macrotask Example (setTimeout and setImmediate) 
  
    setTimeout(() => console.log("setTimeout"), 0);
    setImmediate(() => console.log("setImmediate"));

    console.log("End");

Output: 

  
    End
    setTimeout
    setImmediate


4. Execution Order Summary
Operation Type Execution Order
console.log() Synchronous Runs immediately
process.nextTick() Microtask Runs after sync code, before other async tasks
Promise.then() Microtask Runs after sync code and nextTick
setTimeout() Macrotask Runs in Timers Phase
setImmediate() Macrotask Runs in Check Phase
I/O Callbacks Macrotask Runs in Poll Phase

Mixed Task Queues Example: 
  
    console.log("Start");

    setTimeout(() => console.log("setTimeout"), 0);
    setImmediate(() => console.log("setImmediate"));

    process.nextTick(() => console.log("process.nextTick"));
    Promise.resolve().then(() => console.log("Promise resolved"));

    console.log("End");

Output: 

  
    Start
    End
    process.nextTick
    Promise resolved
    setTimeout
    setImmediate

1. Adapter Pattern

Definition:

The Adapter pattern acts as a bridge between two incompatible interfaces, allowing them to work together without modifying their existing implementations.


Purpose:

  • Legacy System Integration: Helps modern applications interact with outdated or third-party libraries without modifying them.
  • Standardization: Allows different components with varying interfaces to work seamlessly in a unified system.
  • Flexibility: Makes it easier to swap components without major refactoring. 
    
    class XMLResponse {
        getData() {
            return `John Doe30`;
        }
    }

    class JSONAdapter {
        constructor(xmlResponse) {
            this.xmlResponse = xmlResponse;
        }

        getData() {
            const xml = this.xmlResponse.getData();
            return {
                name: xml.match(/(.*?)<\/name>/)[1],
                age: parseInt(xml.match(/(.*?)<\/age>/)[1], 10)
            };
        }
    }

    // Usage
    const xmlResponse = new XMLResponse();
    const adaptedResponse = new JSONAdapter(xmlResponse);
    console.log(adaptedResponse.getData()); // { name: 'John Doe', age: 30 }

2. Bridge Pattern

Definition:

The Bridge pattern decouples an abstraction from its implementation, allowing both to evolve independently without affecting each other.


Purpose:

  • Separation of Concerns: Keeps high-level logic separate from low-level implementation details.
  • Extensibility: Makes it easier to add new variations of abstraction or implementation without modifying existing code.
  • Better Maintainability: Reduces code duplication by using composition instead of inheritance. 
    
    class NotificationSender {
        send(message) {
            throw new Error("Method not implemented.");
        }
    }
          
    class EmailSender extends NotificationSender {
        send(message) {
            console.log(`Sending email: ${message}`);
        }
    }
          
    class SMSSender extends NotificationSender {
        send(message) {
            console.log(`Sending SMS: ${message}`);
        }
    }
          
    class Notification {
        constructor(sender) {
            this.sender = sender;
        }
          
        notify(message) {
            this.sender.send(message);
        }
    }
          
    // Usage
    const emailNotification = new Notification(new EmailSender());
    emailNotification.notify("Your order has been shipped."); // Sending email: Your order has been shipped.
          
    const smsNotification = new Notification(new SMSSender()); // Sending SMS: Your OTP is 123456.
    smsNotification.notify("Your OTP is 123456.");

3. Composite Pattern

Definition:

The Composite pattern organizes objects into tree structures, allowing clients to treat individual objects and compositions of objects uniformly.


Purpose:

  • Hierarchical Data Structures: Simplifies operations on nested structures like file systems or UI elements.
  • Uniformity: Provides a consistent way to handle both single and grouped objects.
  • Scalability: Enables complex object compositions without increasing code complexity. 
    
    class FileComponent {
        show() {
            throw new Error("Method not implemented.");
        }
    }
          
    class File extends FileComponent {
        constructor(name) {
            super();
            this.name = name;
        }
          
        show() {
            console.log(`File: ${this.name}`);
        }
    }
          
    class Folder extends FileComponent {
        constructor(name) {
            super();
            this.name = name;
            this.children = [];
        }
          
        add(child) {
            this.children.push(child);
        }
          
        show() {
            console.log(`Folder: ${this.name}`);
            this.children.forEach(child => child.show());
        }
    }
          
    // Usage
    const root = new Folder("root");
    const file1 = new File("file1.txt");
    const file2 = new File("file2.txt");
    const subFolder = new Folder("subFolder");
          
    subFolder.add(new File("subFile1.txt"));
    root.add(file1);
    root.add(file2);
    root.add(subFolder);
          
    root.show();

    // OutPut
    Folder: root
    File: file1.txt
    File: file2.txt
    Folder: subFolder
    File: subFile1.txt

4. Decorator Pattern

Definition:

The Decorator pattern dynamically adds behaviors or responsibilities to objects at runtime without altering their base structure.


Purpose:

  • Flexible Functionality Extension: Allows adding features to objects without modifying their original implementation.
  • Alternative to Subclassing: Reduces the need for deep inheritance hierarchies.
  • Reusable Components: Enables dynamic feature composition without affecting unrelated objects. 
    
    class APIService {
        request(data) {
            console.log("API Request:", data);
        }
    }
          
    class LoggingDecorator {
        constructor(service) {
            this.service = service;
        }
          
        request(data) {
            console.log("Logging request:", data);
            this.service.request(data);
        }
    }
          
    // Usage
    const apiService = new LoggingDecorator(new APIService());
    apiService.request({ endpoint: "/users", method: "GET" });
    
    // Output
    Logging request: :  {
                            "endpoint": "/users",
                            "method": "GET"
                        }

    API Request: :      {
                            "endpoint": "/users",
                            "method": "GET"
                        }

5. Facade Pattern

Definition:

The Facade pattern provides a simplified interface to a complex subsystem, making it easier to use and reducing dependencies.


Purpose:

  • Encapsulation of Complexity: Hides the intricate details of a system behind a single entry point.
  • Improved Code Readability: Reduces the need for clients to interact with multiple components directly.
  • Easier Maintenance: Changes in the underlying system do not affect the client code. 
    
    class PaymentGateway {
        processPayment(amount) {
            console.log(`Processing payment of $${amount}`);
        }
    }
          
    class OrderService {
        placeOrder(product) {
            console.log(`Order placed for ${product}`);
        }
    }
          
    class NotificationService {
        sendNotification(message) {
            console.log(`Notification sent: ${message}`);
        }
    }
          
    class ECommerceFacade {
        constructor() {
            this.payment = new PaymentGateway();
            this.order = new OrderService();
            this.notification = new NotificationService();
        }
          
        completePurchase(product, amount) {
            this.order.placeOrder(product);
            this.payment.processPayment(amount);
            this.notification.sendNotification(`Your order for ${product} has been completed.`);
        }
    }
          
    // Usage
    const ecommerce = new ECommerceFacade();
    ecommerce.completePurchase("Laptop", 1200);

    // Output
    Order placed for Laptop
    Processing payment of $1200
    Notification sent: Your order for Laptop has been completed.

6. Proxy Pattern

Definition:

The Proxy pattern provides a placeholder for another object to control access, enhance security, or optimize performance.


Purpose:

  • Access Control: Restricts direct access to sensitive resources like databases and remote services.
  • Performance Optimization: Useful for lazy loading, caching, and request batching.
  • Logging and Monitoring: Can be used to track requests and responses for auditing purposes. 
    
    class API {
        fetchData(endpoint) {
            console.log(`Fetching data from ${endpoint}`);
            return { data: "Sample data" };
        }
    }
          
    class APIProxy {
        constructor() {
            this.cache = {};
            this.api = new API();
        }
          
        fetchData(endpoint) {
            if (!this.cache[endpoint]) {
                this.cache[endpoint] = this.api.fetchData(endpoint);
            }
            return this.cache[endpoint];
        }
    }
          
    // Usage
    const apiProxy = new APIProxy();
    console.log(apiProxy.fetchData("/users")); // Fetches data
    console.log(apiProxy.fetchData("/users")); // Returns cached data

7. Flyweight Pattern

Definition:

The Flyweight pattern optimizes memory usage by sharing common object instances instead of creating new ones.


Purpose:

  • Memory Efficiency: Reduces the memory footprint when working with large numbers of similar objects.
  • Improved Performance: Minimizes object instantiation overhead in high-performance applications.
  • Data Sharing: Helps manage immutable data structures efficiently. 
    
    class DatabaseConnection {
        constructor(connectionString) {
            this.connectionString = connectionString;
            console.log(`New connection created for ${connectionString}`);
        }
          
        query(sql) {
            console.log(`Executing query on ${this.connectionString}: ${sql}`);
        }
    }
          
    class ConnectionPool {
        constructor() {
            this.connections = {};
        }
          
        getConnection(connectionString) {
            if (!this.connections[connectionString]) {
                this.connections[connectionString] = new DatabaseConnection(connectionString);
            }
            return this.connections[connectionString];
        }
    }
          
    // Usage
    const pool = new ConnectionPool();
          
    const conn1 = pool.getConnection("db://localhost:5432/users");
    const conn2 = pool.getConnection("db://localhost:5432/users");
    const conn3 = pool.getConnection("db://localhost:5432/orders");
          
    conn1.query("SELECT * FROM users");
    conn2.query("SELECT * FROM users");
    conn3.query("SELECT * FROM orders");
          
    console.log(conn1 === conn2); // true (same link used again)
    console.log(conn1 === conn3); // false (different connection)

    // Output
    New connection created for db://localhost:5432/users
    New connection created for db://localhost:5432/orders
    Executing query on db://localhost:5432/users: SELECT * FROM users
    Executing query on db://localhost:5432/users: SELECT * FROM users
    Executing query on db://localhost:5432/orders: SELECT * FROM orders
    true
    false

1. Singleton Pattern

Definition:

The Singleton pattern ensures that a class has only one instance and provides a global point of access to that instance. This helps manage shared resources efficiently.


Purpose:

  • Resource Management: Prevents the creation of multiple instances of objects that should be shared, such as database connections and configuration managers.
    (Example: Using a single instance for API requests to avoid redundant connections.)
  • Global State Management: Provides a single source of truth for shared data across an application.
    (Example: Storing application settings in a single object for consistent access.)
  • Cache: We can use the cache as a singleton object as it can have a global point of reference and for all future calls to the cache object the client application will use the in-memory object.
    (Example: Caching data in memory for faster access in repeated function calls.) 
    
        class ConfigManager {
            constructor() {
              if (ConfigManager.instance) {
                return ConfigManager.instance;
              }
          
              this.configs = {}; // Configuration settings
              ConfigManager.instance = this;
            }
          
            setConfig(key, value) {
              this.configs[key] = value;
            }
          
            getConfig(key) {
              return this.configs[key];
            }
        }
          
        // Usage
        const config1 = new ConfigManager();
        config1.setConfig("theme", "dark");
          
        const config2 = new ConfigManager();
        console.log(config2.getConfig("theme")); // Output: "dark"
        console.log(config1 === config2); // Output: true

2. Factory Pattern

Definition:

The Factory pattern centralizes object creation, allowing clients to request an object without knowing the exact class that creates it. This enhances maintainability and flexibility.


Purpose:

  • Code Reusability: Reduces duplicate code by handling object creation in a single location.
    (Example: Generating different notification types (email, SMS, push) in messaging apps.)
  • Encapsulation: Hides the instantiation logic, making it easier to modify or extend object creation without affecting the client code.
    (Example: Creating payment gateways for various methods (credit card, PayPal) in e-commerce.)
  • Simplified Object Creation: The factory pattern simplifies object creation. Users only need to call a function, passing the necessary parameters, to get a fully initialized object.
    (Example: Building user profiles with default settings in social media apps.) 
    
        class StripePayment {
            process(amount) {
              console.log(`Payment made via Stripe: $${amount}`);
            }
          }
          
          class PayPalPayment {
            process(amount) {
              console.log(`Payment made via PayPal: $${amount}`);
            }
          }
          
          class BitcoinPayment {
            process(amount) {
              console.log(`Payment made via Bitcoin: $${amount}`);
            }
          }
          
          class PaymentFactory {
            static createPayment(method) {
              switch (method) {
                case "stripe":
                  return new StripePayment();
                case "paypal":
                  return new PayPalPayment();
                case "bitcoin":
                  return new BitcoinPayment();
                default:
                  throw new Error("Invalid payment method!");
              }
            }
          }
          
          // Usage
          const payment = PaymentFactory.createPayment("paypal");
          payment.process(100); // Output: Payment made via PayPal: $100

3. Abstract Factory Pattern

Definition:

The Abstract Factory pattern provides an interface for creating families of related objects without specifying their concrete implementations.


Purpose:

  • Cross-Platform Compatibility: Useful when different environments require different implementations of the same functionality.
    (Example: Creating UI components that adapt to different devices (mobile, tablet, desktop) in a design system.)
  • Reduced Coupling: Helps separate object creation logic from the main application, improving scalability.
    (Example: Creating a database connection system that can switch between MySQL, MongoDB, or PostgreSQL without changing the application logic.)
  • Testability: Abstract factories patterns make it very easier to write unit tests and mock objects. By creating a factory interface, we can simply create mock or test-specific implementations to facilitate testing without affecting the rest of our code.
    Mocking different payment gateways (Stripe, PayPal) for testing in e-commerce platforms. 
    
        class MySQLConnection {
            connect() {
              console.log("Connected to MySQL database.");
            }
          }
          
          class MongoDBConnection {
            connect() {
              console.log("Connected to MongoDB database.");
            }
          }
          
          class SQLFactory {
            static createConnection() {
              return new MySQLConnection();
            }
          }
          
          class NoSQLFactory {
            static createConnection() {
              return new MongoDBConnection();
            }
          }
          
          class DatabaseFactory {
            static getFactory(type) {
              switch (type) {
                case "SQL":
                  return SQLFactory;
                case "NoSQL":
                  return NoSQLFactory;
                default:
                  throw new Error("Invalid database type!");
              }
            }
          }
          
          // Usage
          const sqlFactory = DatabaseFactory.getFactory("SQL");
          const sqlConnection = sqlFactory.createConnection();
          sqlConnection.connect(); // Output: Connected to MySQL database.

4. Builder Pattern

Definition:

The Builder pattern allows step-by-step construction of complex objects by separating object creation from its representation.


Purpose:

  • Manage Complex Object Creation: Useful when an object requires multiple optional parameters.
    (Example: Building a customized car configuration where users select different options for color, engine type, and features.)
  • Improved Readability: Avoids large constructors and allows configuring objects progressively.
    (Example: Constructing a user profile with optional fields like address, phone number, and profile picture.)
  • Flexible Object Construction: It provides flexibility by allowing different configurations for constructing objects.
    (Example: Creating a vacation package where users can choose flight, hotel, and activities according to their preferences.) 
    
        class HttpRequestBuilder {
            constructor() {
              this.request = {
                method: "GET",
                headers: {},
                body: null,
              };
            }
          
            setMethod(method) {
              this.request.method = method;
              return this;
            }
          
            setUrl(url) {
              this.request.url = url;
              return this;
            }
          
            setHeaders(headers) {
              this.request.headers = headers;
              return this;
            }
          
            setBody(body) {
              this.request.body = body;
              return this;
            }
          
            build() {
              return this.request;
            }
          }
          
          // Usage
          const request = new HttpRequestBuilder()
            .setMethod("POST")
            .setUrl("https://api.example.com/login")
            .setHeaders({ "Content-Type": "application/json" })
            .setBody(JSON.stringify({ username: "admin", password: "1234" }))
            .build();
          
          console.log(request);

          // {method: 'POST', headers: {…}, body: '{"username":"admin","password":"1234"}', url: 'https://api.example.com/login'}

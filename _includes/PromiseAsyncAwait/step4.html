When working with Promises in JavaScript, effectively handling errors is crucial for maintaining the stability and reliability of your asynchronous code. Let's delve into how errors are handled using Promises.

Errors Inside Promises

Suppose you have a function called fetchUserData() that returns a Promise:

    
    function fetchUserData(userId) {
        return new Promise((resolve, reject) => {
            resolve({
                userId: userId,
                username: 'john_doe'
            });
        });
    }
Normal Errors

First, let's modify the fetchUserData() function to throw an error outside the Promise if the userId is not a positive number: 

    
    function fetchUserData(userId) {
        if (typeof userId !== 'number' || userId <= 0) { 
            throw new Error('Invalid user ID argument'); 
        } 
        
        return new Promise((resolve, reject)=> {
            resolve({
                userId: userId,
                username: 'john_doe'
            });
        });
    }

Now, handle the Promise using both the .then() and .catch() methods:

    
    fetchUserData('invalid')
        .then(userData => console.log(userData.username))
        .catch(error => console.log(`Caught by .catch: ${error.message}`));

The code will throw an error:

    
    Uncaught Error: Invalid user ID argument

When an exception is raised outside the Promise, it must be caught using a try/catch block:

    
    try {
        fetchUserData('invalid')
            .then(userData => console.log(userData.username))
            .catch(error => console.log(`Caught by .catch: ${error.message}`));
    } catch (error) {
        console.log(`Caught by try/catch: ${error.message}`);
    }

Output:

    
    Uncaught Error: Invalid user ID argument
Errors Within Promises

Let's change the fetchUserData() function to throw an error inside the Promise if the user is not authorized: 

    
    let authorized = false;
    
    function fetchUserData(userId) {
        return new Promise((resolve, reject) => {
            if (!authorized) {
                reject(new Error('Unauthorized access to user data'));
            }

            resolve({
                userId: userId,
                username: 'john_doe'
            });
        });
    }

And consume the Promise:

    
    try {
        fetchUserData(10)
            .then(userData => console.log(userData.username))
            .catch(error => console.log(`Caught by .catch: ${error.message}`));
    } catch (error) {
        console.log(`Caught by try/catch: ${error.message}`);
    }

Output:

    
    Caught by .catch: Unauthorized access to user data

If you throw an error inside the Promise, it will be caught by the .catch() method, not the try/catch block.

If you chain Promises, the .catch() method will handle errors that occur in any Promise.

For example: 

    
    promise1
        .then(promise2)
        .then(promise3)
        .then(promise4)
        .catch(error => console.log(error.message));

In this example, if any error occurs in promise1, promise2, or promise4, the .catch() method will handle it.

Missing the .catch() Method

The following example does not provide the .catch() method to handle errors inside the Promise. This will result in a runtime error and terminate the program: 

    
    function fetchUserData(userId) {
        return new Promise((resolve, reject) => {
            if (!authorized) {
                reject('Unauthorized access to user data');
            }
            resolve({
                userId: userId,
                username: 'john_doe'
            });
        });
    }
    
    try {
        fetchUserData(10)
            .then(userData => console.log(userData.username));
        // The following code will not execute
        console.log('next');
    } catch (error) {
        console.log(`Caught by try/catch: ${error}`);
    }

Output:

    
    Uncaught (in promise) Unauthorized access to user data

If the Promise is resolved, you can omit the .catch() method. However, a potential error in the future may cause the program to unexpectedly terminate.

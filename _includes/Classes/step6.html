Class patterns, also known as design patterns, are established solutions to common problems encountered while designing and coding software using classes and objects. These patterns provide reusable approaches to structuring code, solving specific problems, and improving code quality, maintainability, and scalability. Some popular class patterns include:


  1. Singleton Pattern: Ensures that a class has only one instance and provides a global point of access to that instance.

  2. Factory Pattern: Provides an interface for creating instances of objects, allowing subclasses or specialized methods to handle object creation.

  3. Observer Pattern: Defines a one-to-many dependency between objects so that when one object changes state, all its dependents (observers) are notified and updated automatically.

  4. Adapter Pattern: Allows incompatible interfaces of classes to work together by wrapping an existing class with a new interface.

  5. Decorator Pattern: Dynamically adds new functionality to objects without altering their structure, allowing behavior to be added to individual objects.

  6. Strategy Pattern: Defines a family of algorithms, encapsulates each one, and makes them interchangeable. This allows the algorithm to vary independently from the clients that use it.

  7. Facade Pattern: Provides a unified interface to a set of interfaces in a subsystem, simplifying and hiding the complexity of the subsystem from the client.

  8. Command Pattern: Encapsulates a request as an object, thereby allowing for parameterization of clients with queues, requests, and operations.

  9. Template Method Pattern: Defines the skeleton of an algorithm in the superclass but allows subclasses to override specific steps of the algorithm without changing its structure.

  10. Iterator Pattern: Provides a way to access elements of an aggregate object sequentially without exposing its underlying representation.

These patterns, among others, serve as proven solutions to common design challenges encountered when working with classes and objects in object-oriented programming. They aim to promote flexibility, maintainability, and scalability while improving code organization and reusability. Choosing the right pattern depends on the specific problem being solved and the context in which it's applied.


Examples of Class Patterns

Singleton Pattern

Ensures only one instance of "HeroProfile" is created.



class HeroProfile {
  constructor(name, age, power) {
    if (!HeroProfile.instance) {
      this.name = name;
      this.age = age;
      this.power = power;
      HeroProfile.instance = this;
    }
    return HeroProfile.instance;
  }
}
  
  const hero1 = new HeroProfile('Superman', 30, 'Flight');
  const hero2 = new HeroProfile('Batman', 35, 'Intelligence');
  
  console.log(hero1 === hero2); // Output: true (same instance)
Factory Pattern

Provides a factory method to create instances of "HeroProfile".



class HeroProfile {
  constructor(name, age, power) {
    this.name = name;
    this.age = age;
    this.power = power;
  }
  
  static createHero(name, age, power) {
    return new HeroProfile(name, age, power);
  }
}
  
const hero = HeroProfile.createHero('Wonder Woman', 25, 'Super Strength');
console.log(hero); // Output: HeroProfile { name: 'Wonder Woman', age: 25, power: 'Super Strength' }
Observer Pattern

Simulates an observer pattern where other objects can observe changes in a hero's power.



class HeroProfile {
  constructor(name, age, power) {
    this.name = name;
    this.age = age;
    this._power = power;
    this.observers = [];
  }
  
  get power() {
    return this._power;
  }
  
  set power(newPower) {
    this._power = newPower;
    this.notifyObservers();
  }
  
  addObserver(observer) {
    this.observers.push(observer);
  }
  
  notifyObservers() {
    this.observers.forEach(observer => observer.update(this._power));
  }
}
  
class PowerObserver {
  update(power) {
    console.log(`Hero's power has been updated: ${power}`);
  }
}
  
const hero = new HeroProfile('Flash', 28, 'Super Speed');
const observer1 = new PowerObserver();
const observer2 = new PowerObserver();
  
hero.addObserver(observer1);
hero.addObserver(observer2);
  
hero.power = 'Time Travel';
// Output:
// "Hero's power has been updated: Time Travel"
// "Hero's power has been updated: Time Travel"
